# Naming standards by object type

Loaded from `SKILL.md` Stage 1. The four stages stay fixed; this file adjusts **method weighting, judging emphasis, and special checks** per type.

## Commercial product / App

- **Method weighting**: Metaphor (2), Compound (3), Wordplay (6) lead. Descriptive (1) only as functional sub-brand material; Acronym (7) has high communication cost for consumers — de-prioritize.
- **Judging emphasis**: tone match and headroom count double — the name must survive category expansion (many "XX买菜" companies later renamed for this reason).
- **2026 note**: the "AI-suffix + generic noun" pattern now reads as founder laziness; distinctive names stand out more than ever. Voice-assistant and AI-search pronounceability makes fluency extra valuable.
- **Special checks**: tagline mandatory; remind the user that trademark similarity, domains, and app-store collisions need human verification. Consumer-facing apps weight fluency highest; pro/B2B products may trade fluency for trust-tone.
- On the Distinctiveness Spectrum, push candidates from Descriptive toward Suggestive before scoring.

## Company / team

- **Method weighting**: Metaphor (2), Compound (3) lead; the name must hold up on an "About us" page and in formal documents (contracts, name cards).
- **Judging emphasis**: headroom is the heaviest dimension — business will pivot; the name must absorb it.
- **Special checks**: resonance in formal register; no meaning drift when the company diversifies.

## Open-source project / tech library

- **Method weighting**: Coined (4), Borrowed proper noun (5), Acronym (7) gain weight — engineer-flavored register is part of the tone; Descriptive (1) is also respectable here (naming what it does is a virtue in tech).
- **Language**: English primary; the Chinese pair may be omitted.
- **Special checks**: spelling stability (all-lowercase, no hyphen ambiguity); remind the user to check npm / PyPI / GitHub name collisions; project name and product name may diverge (the repo name need not carry trademark weight, e.g. React).

## Event / column / series

- **Method weighting**: Metaphor (2), Wordplay (6) lead — atmosphere plus punch.
- **judging emphasis**: fluency is the heaviest dimension; event names get spoken and chanted.
- **Special checks**: sustainability across years/seasons — a name embedding "2026" dies in January.

## Offline shop / store / restaurant

- **Method weighting**: Descriptive clarity gains legitimate weight back — a shop name is read at walking speed from a moving sidewalk. Category name must appear or be instantly inferable (巴奴毛肚火锅, 沙县小吃); the distinctive part carries the brand.
- High-yield shop patterns: 姓氏+品类 (老王煎饼 — trust mark), 地名+品类, 成语改造 (茶颜悦色 from 和颜悦色), 人设+品类 (霸王茶姬), 吉利彩头 formats for tradition trades.
- **Judging emphasis**: the 门头 test outranks cleverness — can a person walking past at 3 meters read and parse the name in 2 seconds? Full name must be natural to say aloud when ordering ("来一杯…"). Check searchability on 大众点评/美团/高德 — the name is also a search keyword.
- **Trademark timing is life-or-death for shops**: file BEFORE the store opens and before any press (鹿角巷 filed too late and drowned in 7000 copycats; 皇茶 couldn't register and had to buy 喜茶 for ¥700k); defensively register the near-variant ring (茶颜观色 squatting war).
- **Special checks**: same-neighborhood duplicate names; region-wide density of the name.

## Person (baby / pen name / 艺名)

- Person names get their own rulebook — load `references/person-naming.md` and run it in place of the brand-oriented checks (full-name homophone sweep, tonal curve, era-collision, characters-system safety, pinyin internationalization, family customs as constraints).

## Fallback: everything else

Return to the Positioning Statement's feeling: professional leanings favor methods 1/5, warm leanings favor 2/6, premium leanings favor 4/5. Whichever emotion the statement carries, let that method family carry the ideation.
